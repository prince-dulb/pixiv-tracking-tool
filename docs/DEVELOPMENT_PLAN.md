### 3.2 画廊翻页 ✅（2026-06-16 完成）

#### 需求描述

画廊当前硬编码 `.limit(200)`，超出作品无法查看。需要翻页/加载机制。

#### 方案：设置可选 A（页码翻页）或 C（无限滚动），默认 C

**模式 A：页码翻页**
- URL 参数 `?page=2`，底部页码栏
- 每页 N 件（默认 200，设置里可配）
- 切换页码时页面跳转到顶部
- 筛选条件在翻页间保持

**模式 C：无限滚动（默认）**
- 页面滚动到底部时自动 AJAX 加载下一批
- 新卡片追加到画廊末尾，无页面跳转
- URL 参数通过 `history.pushState` 静默更新（可选，方便分享当前滚动位置）
- "加载中"骨架屏或底部加载指示器

**设置项：**
- 翻页模式：页码 / 无限滚动（默认无限滚动）
- 每页/每批数量：50 / 100 / 200 / 500（默认 200）
- 最大可见作品数：不限 / 600 / 1200 / 3000（默认不限）—— 仅无限滚动模式生效

#### 预判问题与对策

| 问题 | 结论 | 对策 |
|------|------|------|
| 无限滚动会不会爆内存？ | 不会 | 每个卡片 DOM ~500B，1000 张才 500KB。图片用 `loading="lazy"`，屏幕外不加载。瓶颈是图片纹理而非 DOM |
| 滚太深回不去顶部？ | 会烦人 | 右下角固定"回到顶部"浮动按钮，滚动超过 3 屏时出现 |
| 筛选条件变了，已加载的怎么处理？ | 应该重置 | 切换画师/类型筛选时重置已加载列表，从头开始。不混数据 |
| 无限滚动 + 已隐藏切换冲突？ | 不冲突 | "显示已隐藏"只是筛选条件之一，切换时同样重置 |
| 网络慢时连续触发多次加载？ | 需防抖 | 加载中时 `isLoading` 标记，忽略重复触发 |

#### 实现要点

**后端：**
- `GET /` 新增 `offset` 和 `fragment` 参数
- `fragment=1` 时返回仅含卡片 HTML 的片段（不含完整页面），供 AJAX 追加
- 响应头标记 `X-Has-More: 1` 或 `0`，前端据此决定是否继续监听

**前端（模式 C）：**
- `IntersectionObserver` 监听画廊底部 sentinel 元素
- 进入视口 → `fetch('/?offset=200&fragment=1&...')` → 解析 HTML → `insertAdjacentHTML('beforeend', ...)`
- 加载中时底部显示 spinner
- 筛选条件变化时清空画廊 + 重置 offset

**前端（模式 A）：**
- 传统 URL 参数 `?page=2`，后端根据 `page` 计算 offset
- 底部页码栏：`< 1 2 3 ... 10 >`
- 翻页时 `window.scrollTo(0, 0)`

**回到顶部按钮：**
- `position: fixed; bottom: 24px; right: 24px`
- 滚动超过 `window.innerHeight * 2` 时淡入，否则淡出
- 点击 → `window.scrollTo({top: 0, behavior: 'smooth'})`

### 3.4 收藏/取消收藏 ✅（2026-06-16 完成）

#### 需求澄清（2026-06-15）

**收藏 API：**
- 仅公开收藏（`restrict="public"`），不提供私有选项

**状态同步（三个维度）：**

| 场景 | 行为 |
|------|------|
| 新作品下载 | 下载完成后异步查询 Pixiv 该作品的收藏状态，写入 `is_bookmarked` |
| 已有作品 | 提供一次性全量同步入口——遍历所有已下载作品，逐条查询收藏状态（走已有 `_throttle` 1 req/s），需进度提示 |
| 手动操作 | 详情页/画廊卡片/画师作品页点击按钮，即时切换 |

**UI 位置：**
- 画廊卡片：hover 时右下角叠加心形按钮（类似 Pinterest）
- 画师作品页：每个作品条目增加收藏入口
- 详情页：按钮放在画作展示区（page-viewer）右下角，顶部操作栏移除收藏按钮

**错误反馈：**
- 操作失败弹出自动消失的 toast 消息
- 成功时按钮状态切换即为反馈，无需弹窗

**交互方式：**
- 必须 AJAX 化（`fetch`），不刷新页面
- 原因：配合无限滚动时保留滚动位置；详情页避免不必要的整页重载

#### 预判问题与对策

| # | 问题 | 对策 |
|---|------|------|
| 1 | 全量同步大量作品会打大量 API 请求 | 走已有 `_throttle`（1 req/s），显示进度条 |
| 2 | 新作品下载时已在打 API，再加收藏查询增加限流压力 | 下载完成后异步逐张查询，间隔至少 1s |
| 3 | 画廊卡片空间有限，收藏按钮放哪 | hover 时右下角叠加心形按钮 |
| 4 | 已隐藏作品能否取消收藏 | 能，两个操作独立；隐藏只是本地过滤 |
| 5 | 详情页按钮移到 page-viewer 右下角——多页作品怎么放 | 固定在 page-viewer 容器右下角，各页独立滚动不重叠 |
| 6 | `is_bookmarked` 需要从 Pixiv API 的 illust detail 中获取 | `_parse_illust` 增加提取 `is_bookmarked` 字段；客户端已有 `get_illust_detail` |
| 7 | 收藏按钮和无限滚动的位置保存 | AJAX 化后页面不刷新，滚动位置自然保留 |

#### 实现要点

**后端：**
- `client.py`：`_parse_illust` 增加 `is_bookmarked` 字段提取
- `routes/works.py`：`POST /illust/{illust_id}/bookmark` 改为返回 JSON（不再重定向）
- `tracker.py`：下载完成后调用 `get_illust_detail` 查询该作品收藏状态
- 新增 `POST /api/bookmarks/sync` 端点，全量同步已有作品收藏状态（后台线程 + 进度）

**前端（详情页）：**
- 按钮从顶部 `.detail-actions` 移到 `.page-viewer` 容器右下角
- `fetch` 替代表单 POST，更新按钮状态无需刷新
- 失败时 toast 弹窗

**前端（画廊卡片 + 画师作品页）：**
- 卡片 hover 时右下角叠加心形按钮
- 同样 `fetch` + toast 模式

**Toast 组件：**
- 页面底部居中，`position: fixed; bottom: 24px;`
- 出现后 3 秒自动淡出
- 纯 JS 实现，无依赖

## 七、版本号与 Git 约定

- 版本号格式：`v{major}.{minor}.{patch}`（如 v0.0.6）
- 每个版本从 master 开 worktree 分支开发
- 开发完成后合并 master + 打 tag + GitHub Release
- release 目录：`release/vX.Y.Z/`，包含 `.exe` + `.env.example`
- 构建命令：`cd app && pyinstaller build.spec --distpath ../release/vX.Y.Z --workpath build_tmp --clean`

---

## 八、架构注意事项

- SQLite 单文件，多线程 WAL 模式
- 无前端框架，Jinja2 SSR + 原生 JS，遵循传统 POST + Redirect 模式
- 所有后台任务走 `threading.Thread(daemon=True)` 异步
- 图片服务走 FastAPI `FileResponse`，`loading="lazy"` 懒加载
- CSS 变量统一管理主题色（`:root` 在 style.css）
